Las características de PostgreSQL se entienden mejor si se agrupan por facetas, tal como las organiza el material del proyecto: modelo de datos, concurrencia, integridad, seguridad, disponibilidad, extensibilidad y plataforma. Cada faceta responde una pregunta distinta que conviene hacerse antes de elegir un gestor para un proyecto real.

Modelo de datos y SQL

PostgreSQL es un SGBD relacional con características objeto-relacionales: además de tablas y relaciones, su catálogo almacena funciones, tipos y operadores definidos por el usuario. Expone un SQL de cumplimiento amplio del estándar —JOIN, CTE, funciones de ventana— y organiza los objetos en esquemas independientes que conviven dentro de la misma base de datos.

Los tipos avanzados permiten modelar sin tablas auxiliares: JSONB para documentos semiestructurados, arrays para colecciones homogéneas, rangos para intervalos y tipos compuestos para registros. Sobre esa base, vistas, funciones, triggers y procedimientos almacenados llevan la lógica repetida al servidor.

CaracterísticaQué implicaPara qué te sirve
JSONB, arrays y rangos Tipos nativos con operadores e índices propios (GIN). Guardar documentos o listas sin romper el modelo relacional.
Vistas y funciones Consultas y lógica reutilizables definidas en el servidor. Centralizar reglas y reducir código repetido en la aplicación.
Triggers y procedimientos Código que se ejecuta ante un evento o bajo demanda. Auditar y validar automáticamente cada cambio de datos.
Esquemas Espacios de nombres dentro de una misma base de datos. Aislar módulos de distintos proyectos en un único servidor.
Cumplimiento SQL Soporte amplio de subconsultas, uniones y ventanas. Escribir consultas portables entre distintos gestores.

Concurrencia, rendimiento e integridad

Concurrencia y rendimiento

La concurrencia se resuelve con MVCC: cada transacción ve una instantánea del dato y las lecturas nunca bloquean las escrituras. El nivel de aislamiento por defecto es READ COMMITTED y puede subirse a REPEATABLE READ o SERIALIZABLE según lo que la aplicación necesite. El rendimiento lo apoyan el particionado declarativo, las consultas paralelas, el autovacuum que libera espacio y un planificador basado en costos que usa las estadísticas recolectadas por ANALYZE.

Idea clave

READ COMMITTED es el nivel por defecto: cada sentencia ve los cambios confirmados al iniciarse. Al subir a SERIALIZABLE el motor detecta y rechaza conflictos, por lo que la aplicación debe estar preparada para reintentar la transacción.

El tipo de índice se elige según la forma de consulta:

  • B-tree — igualdad y rangos; es el índice por defecto.
  • Hash — búsquedas de igualdad sobre una columna.
  • GiST — geometría y rangos; base de PostGIS.
  • GIN — valores compuestos: JSONB, arrays y texto completo.
  • BRIN — tablas grandes correlacionadas con el orden físico; ocupa muy poco espacio.

Integridad y transacciones

PostgreSQL cumple las propiedades ACID y hace cumplir la integridad declarativa con claves primarias y foráneas, restricciones CHECK y UNIQUE. Para deshacer parcialmente dentro de una transacción se usan guardpoints (SAVEPOINT): PostgreSQL no admite transacciones anidadas como tales.

Seguridad

El control de acceso se organiza en roles y permisos por objeto (tablas, columnas, funciones). La autenticación usa SCRAM-SHA-256 y el tránsito se protege con TLS. La row-level security permite que cada fila lleve su propia condición de acceso, de modo que una misma consulta devuelve resultados distintos según quién la ejecuta. La auditoría se implementa con la extensión pgaudit, y el cifrado en disco se resuelve en el nivel del sistema de archivos o del dispositivo.

Disponibilidad y respaldo

La recuperación se apoya en el WAL archiving: con los registros archivados es posible un PITR, es decir, restaurar la base hasta el instante exacto que se necesita. La replicación en streaming mantiene copias del primario de forma síncrona o ascíncrona, mientras la replicación lógica copia tablas seleccionadas hacia otra instancia o versión. Para respaldos se usan pg_dump (lógicos) y pg_basebackup (imagen completa), y en el ecosistema existen herramientas de alta disponibilidad como Patroni, que automatiza el conmutador por fallo.

Extensibilidad, ecosistema y plataforma

Con CREATE EXTENSION se añaden funcionalidades sin modificar el motor. Los foreign data wrappers permiten consultar datos que viven en otras fuentes —otro gestor, un CSV o una API— como si fueran tablas locales, y los tipos y operadores personalizados amplían el lenguaje. En cuanto a herramientas, conviven psql, pgAdmin y DBeaver, junto con drivers como libpq, psycopg2 y JDBC y los ORMs habituales.

  • PostGIS — consultas espaciales sobre geometrías.
  • pgcrypto — funciones criptográficas dentro de la base.
  • pg_trgm — similitud de cadenas para búsqueda difusa.
  • pg_stat_statements — estadísticas de las consultas ejecutadas.

Multiplataforma y licencia

El servidor corre en Linux, Windows, macOS y BSD, se distribuye como software de código abierto con licencia permisiva —sin costes de licencia ni ataduras de proveedor— y cuenta con una comunidad global que publica documentación, extensiones y versiones estables de forma periódica.

Ideas para llevar

Resumen

1) Las características de PostgreSQL se agrupan en facetas: modelo de datos, concurrencia, integridad, seguridad, disponibilidad, extensibilidad y plataforma. 2) MVCC, los índices y el planificador de costos sostienen el rendimiento; ACID y las restricciones sostienen la integridad. 3) WAL, replicación y PITR sostienen la disponibilidad, y las extensiones amplían el motor sin tocarlo.
